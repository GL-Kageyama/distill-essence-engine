# php2shell — 仕組みを断面で見る（2ページ）

> 事実の台帳は [../php2shell-manga/input.md](../php2shell-manga/input.md) を正とする。ここには**仕組みの2件を断面図にするための整理**だけを置く。

## 2件の違い（ここが2ページの理由）

| | CVE-2026-109618 | CVE-2026-109619 |
|---|---|---|
| 壊れる対象 | **中身** — リクエストデータが途中までしか初期化されない | **参照** — ワーカーの内部状態が、解放済みのメモリを指したまま |
| きっかけ | `memory_limit` に達する（OOM） | 致命的エラー |
| 誤りの瞬間 | **後始末**が、書き終わっていない欄を「有効」として扱う | **次のリクエスト**が、もう無い場所を「まだある」として使う |
| 断面で見えるもの | 同じ列の下半分が空のまま、そこを掴む後始末の腕。指は黒の手前を通る | 同じ列がまるごと空になり、そこを指したまま戻らない棒。次の客が黒に入る |
| 黒（見えないもの） | **まだ書かれていない**領域 | **すでに消された**領域 |

- 両方とも **アプリケーションのコードが動く前**に成立する。だから2ページとも、右下の「アプリ」の扉は一度も開かない。
- 攻撃は 1 回の HTTP POST で足りる。認証は関係ない。**クラッシュは伴わないことがある**（Datadog）。断面図は「静かに壊れる」ことを優先し、爆発や破片は描かない。

## 断面の共通言語

- **部屋**＝PHP のワーカー。断面で切って、切り口に斜線のハッチ。ハッチは等間隔にしない。
- **床のレール**＝リクエストが通る道。上から下へ時間が流れる。
- **奥の壁の格子**＝4×4 の十六枠。**ひとつのリクエスト＝一列**。列の四枠の名は `何をするか` / `送った中身` / `添付` / `設定`——一般読者に読める語にする（特定の実装の構造ではなく例示）。
- **壁に沿う細い棒**＝参照。一枠に一本ずつ収まり、先に小さな矢じり。**両ページに全部ある**（P1 では使われない）。
- **床下の後始末レール**＝後始末。**両ページにある**。P1 は列まで届いて手が伸びる。P2 は列の手前で切れている。
- **右下の扉**＝アプリケーション。2ページとも閉じている。輪郭だけが紙面のどの線よりも太い。下から細い光が漏れるだけ。
- **左の余白の目盛り**＝時刻ではなく段階（到着／処理／後始末）。P2 でも後始末の目盛りは消さず、届かない線として描く。

## 描かないこと

- 爆発・破片・赤い警告・バグの虫・ハッカーの人影・ターミナルの緑文字
- 片方のページにしか無い装置。**棒も後始末レールも、2ページに同じだけ置く**
- 特定のエクスプロイト手順（ペイロード、オフセット、ROP 等）。**仕組みの像**までで止める
- 実在製品の画面・ロゴ
- 吹き出し。**この2ページでは誰も喋らない**。文字は手書きのキャプションとラベルだけ

## 事実と演出

- 事実：109618 は OOM 時にリクエストデータが部分的にしか初期化されず、後始末がそれを有効として扱う。109619 は致命的エラー後にワーカーの状態が解放済みメモリを指したまま残り、次のリクエストが同じワーカーでそれを使う（use-after-free）。両方 CVSS 9.2、修正版 `8.2.35 / 8.3.36 / 8.4.27 / 8.5.12`。アプリの前に成立。
- 演出：部屋・格子・レール・腕・棒・扉・ハッチ・目盛り。列の四枠の名（`何をするか` / `送った中身` / `添付` / `設定`）は説明のための例示。
- 黒は同じ列の同じ位置。**P1 は列の下半分、P2 は列の全体**——同じ縦の帯が、長さだけを変えて二度現れる。
- 断定しない：実際に攻撃された・クラッシュした、という描写はしない。
