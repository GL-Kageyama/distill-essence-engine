# 入力：PHP「php2shell」緊急脆弱性（2026-10-21）→ 4ページ漫画

> 種別＝ニュース／技術解説（一次情報ベース）。**確定した事実**と、**報道・未確認**を分けて書く。漫画の人物・事務所・会話は演出であり、事実の主張ではない。

## 何が起きたか（確定）

- 2026年10月21日 14:00 UTC（**日本時間 23:00**）、PHP が予定を前倒しして緊急セキュリティリリースを公開した。
- 対象は PHP コアの2件。**CVE-2026-109618** と **CVE-2026-109619**。両方 **CVSS v4.0 9.2（Critical）**。通称「php2shell」。
- 修正版は **PHP 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12**。
- **PHP 5.4 以降のすべてのビルドが影響**（Cisco Talos）。PHP 8.1 以前は EOL で公式修正なし。7.4 / 8.0 / 8.1 にはソースのバックポートが出た。ディストロや LTS 事業者のパッケージもある。
- **PHP 8.2 のセキュリティサポートは 2026年12月31日で終了**（Talos）。
- 対象となる Web 実行形態：**Apache mod_php / PHP-FPM / php-cgi / FrankenPHP / LiteSpeed**。最も危険なのは **mod_php**（アプリのコードより前に攻撃が届く）。
- 当初の公開予定は 10月22日だった。10月20日、CVE ID と「CVSS 10.0」という**誤ったスコア**が Hacker News などに漏れ、公開が1日前倒しになった。正しいスコアは 9.2。

## 原因（確定している範囲）

- **CVE-2026-109618（OOM による破損）**：リクエストの処理中に `memory_limit` に達すると、リクエストデータが**部分的にしか初期化されないまま**後始末に入る。後始末の側が、その不正なデータを**有効なものとして扱ってしまう**。
- **CVE-2026-109619（古い状態の再利用）**：致命的エラーが起きたとき、ワーカーの内部状態が**前のリクエストの解放済みメモリ**を指したまま残る。次のリクエストが同じワーカーに来ると、その古い状態を使う（use-after-free）。
- どちらも **アプリケーションのコードが動く前**に成立する。アプリ側のログイン・権限・CMS の更新では防げない。
- 攻撃には、ネットワークから届く PHP のエンドポイントと **1回の HTTP POST** で足りる。認証は不要。クラッシュも総当たりも要らない。ASLR は準備リクエストで回避できる。
- 漏洩した情報では `session.upload_progress` が関与しているとされた。PHP と Talos は、無効化が**確認された経路を塞ぐだけで、完全な修正ではない**としている。
- **2024年**、Sovereign Tech Agency の資金で OSTIF が調整し、Quarkslab が PHP の外部監査を行った。その修正作業の途中で、109618 の兆候が見つかっている。修正は互換性の破壊・新たな DoS のリスク・多数のサードパーティ拡張への影響から**停滞**した。PHP Foundation はこれを「**構造的な失敗**」と明記した。
- **2026年7月30日**に Calif が PHP の監査を開始。**8月11日**に Calif の Ryan A が「同じ根本原因で無条件の RCE」を報告。**OpenAI も同日に同じ根本原因を報告**。**Wiz が8月24日**、**OpenAI が9月18日**に追加の経路を報告。Trail of Bits も監査した。
- PHP のセキュリティチームは7月1日以降 **15件の CVE** を公開し、**100件以上**の無効・重複・再現不能の報告を処理した。

## 悪用・攻撃（報告が割れている）

- **未確認とする側**：CISA（公開時点）、Cisco Talos（10/21 14:00 UTC 時点）、watchTowr、Huntress、オーストラリア ACSC、日本の IPA。
- **観測したとする側**：Cloudflare の CTO Dane Knecht が「初期の攻撃」を観測し、緊急の WAF ルールを投入した。Patchstack は、ホスティング事業者が **10/21 07:34 UTC 頃**に悪用を報告したと述べた。
- Calif が**PoC の動画を誤って公開**し、コピーが拡散した。PHP は公開時点で「機能する攻撃コードは確認していない」としている。
- 攻撃でできること：ワーカーのメモリ読み取り（セッショントークン・API キー・証明書）、任意コード実行、Web シェル、cron やアカウントの追加による永続化。
- **落ちるとは限らない**。Datadog は「悪用は静かで、ワーカーのクラッシュを伴わないことがある」としている。

## 影響（数字と、報道）

- **W3Techs**：サーバー側の言語が分かるサイトのうち、PHP は約 **69〜70%**（2026年9月〜10月の取得値）。**WordPress は全サイトの約43%**。
- **Censys（10/21）**：インターネットから見える PHP のホスト **2,580,515**、Web プロパティ **54,888,147**。版を報告した **1,577,394** ホストのうち **1,575,688** が修正版より古い。**約115万**が PHP 8.1 以前。※版の自己申告なので上限値。ディストロのバックポートで修正済みの可能性がある。
- **VirusTotal**：PHP に関連する IP 約 **510万**。うち WordPress 約53.8万、Laravel 約14.1万、Nextcloud 約10.7万。
- **国内（確定）**：コドモンが10月21日、**保護者アプリを含む全サービス**を予防的に停止した。発表は「重大な脆弱性」で、**PHP とは明言していない**。不正アクセス・情報漏えいは「現時点で確認されていない」。10月22日早朝の再開を見込んでいた（再開の確定告知は未確認）。施設向けに**代替運用のテンプレート**（保護者通知・登降園記録簿・出席簿。ダウンロード可）を提供した。刈谷市は10月22日以降の出欠を**紙で確認**すると案内した。
- **国内（報道）**：同日、BASE、pixiv、DMM.com、niconico、さくらのレンタルサーバ、X Server、グランブルーファンタジー、ウマ娘などが緊急メンテ／一部停止した。**PHP との因果は各社の発表では確認されておらず**、メディアは「この対応のためと見られる」としている。
- **欧州**：CERT-EU は、直ちに修正できない場合、インターネット公開アプリを**外部ネットワークから切り離す／公開を止める**よう勧告した。一部報道はオランダ・フィンランド・フランス・デンマークの政府サイト停止を伝えるが、**一次情報では確認できていない**。漫画では勧告だけを描く。
- **埋め込み**：Plesk の管理パネル自身の PHP（sw-engine）は 8.4.24/8.4.25 のままで、修正版 8.4.27 未満。ホットフィックスの作業中とされる。cPanel も対象。製品・管理パネル・アプライアンスの中の PHP は、ホスト側の更新では直らないことがある。

## 対応（一次情報）

### 個人・小規模サイト

1. **版を見る**（`php -v`、`phpinfo()`、ホスティングの管理画面）。
2. **修正版へ更新**：8.2.35 / 8.3.36 / 8.4.27 / 8.5.12。共用サーバーなら事業者に確認する。
3. **更新後にワーカーを全部再起動**する（PHP-FPM / Apache など）。古いワーカーは古いコードのまま動き続ける。
4. **WordPress の自動更新では PHP は直らない**。CMS・プラグイン・テーマの更新は別物。
5. すぐ直せないなら、**公開を止める**。
6. 一時しのぎ（**完全な修正ではない**）：`session.upload_progress.enabled=0`（php.ini か FPM プール設定。`ini_set()` / `.user.ini` では不可）、`memory_limit=-1`、`post_max_size` の縮小、PHP 8.5 では `fatal_error_backtraces=0`。設定後は全ワーカーを再起動。
7. **侵害確認**：PHP のワーカーが shell やダウンロードツールを産んでいないか、cron・新規アカウント・見慣れないファイル。

### 法人

1. **全 PHP の棚卸し**。製品・管理パネル・アプライアンス・EOL 版・忘れられたホストを含める。
2. **インターネット公開の mod_php から優先**。次に PHP-FPM / php-cgi / FrankenPHP / LiteSpeed。
3. 修正版へ更新し、**再起動後に実際の稼働版を確認**する。
4. PHP 8.1 以前は、ディストロ／LTS のバックポート → サポート版への移行 → 隔離・停止の順。
5. WAF は**時間稼ぎ**。修正の代わりにはならない。
6. 監視・ログ保全・インシデント対応。ワーカーが shell を産む挙動を検知する。

## ⑧ 忠実性（この漫画が変えてはいけないこと）

- 人物（佐倉ミナ／橘）、会社「コモレビネット」、松本市の運用室は**演出**。実在の人物・企業・施設ではない。
- 実在サービスの画面・ロゴは描かない。一般化した管理画面・端末にする。社名・自治体名はキャプションの文字に限る。
- コドモンの停止は**事実**。ただし原因を PHP と断定しない（同社の発表は「重大な脆弱性」）。
- 刈谷市が10月22日以降の出欠を紙で確認すると案内したことは**事実**。
- 台所の紙の「出席確認票」は、コドモンが施設向けに配った**代替運用テンプレート**（保護者通知・登降園記録簿・出席簿。ダウンロード可）と、刈谷市の紙での出欠確認の案内を一般化したもの。特定の家庭・施設ではない。P1 の用紙と同じ罫線・同じ途中の埋まり方にして、視覚的に韻を踏む。
- 国内の他サービスの停止は**事実**。PHP との因果は**断定しない**（「緊急メンテに入った」まで）。
- 欧州の政府サイト停止は一次情報で確認できないため**描かない**。CERT-EU の勧告として描く。
- 「すでに大規模に攻撃されている」と断定しない。**報告が割れている**ことを事実として扱う。P2 はページ隅に「想定されるパターン」と明記し、最後に「まだ、見つかっていない」と言う。
- 数字は白板に三行だけ（`PHP 7割（言語が分かるサイト）` / `WordPress 43%（全サイト）` / `258万台（ネットから見える）/ 版を返した158万台のうち、115万台が8.1以前`）。母数を一行で確定させ、曖昧なまま並べない。小さく `出典: W3Techs / Censys`。Censys は版の自己申告なので上限値。
- **時刻（22:58 / 03:12 / 07:10 / 07:31）、03:12 の shell、プロセス ID、cron 行、`.cache/idx.php`、`svc-backup` は、想定シナリオの演出**。実際にその時刻・そのパスで攻撃があったという報告ではない。
- P4 の `Plesk 内 PHP：8.4.25` は事実（管理パネル自身の PHP が修正版未満）。`8.1（EOL）` も事実。`session.upload_progress.enabled=0` は一時しのぎで、**完全な修正ではない**。
- 白板のゲートは「修正版で検査が入る」ことの演出。アーキテクチャが変わったという主張ではない。テープの版番号の書き換え、ラックの上に貼られた修正版の一覧（一つに鉛筆の二重線）も演出。
- P3 の通りの窓口（同じ机・同じ係員・同じフックが窓ごとに並ぶ）は比喩の演出。実在の建物・会社ではない。P3 の小さな注記「（各社の発表・報道より）」は、実在の出来事を台詞ではなく出典の注記として置くため。
- 個人・法人の対応は、一次情報の推奨を**断定の口調にしすぎない**。「〜する」「〜が望ましい」の範囲で。

## 4ページ設計（テーマ×選んだ一点×間接の装置）

| Page | テーマ | 選んだ一点（particular） | 間接の装置（indirect） |
|---|---|---|---|
| 1 | 原因（どういう言語バグか） | 書く前の用紙に、スタンプが「有効」を押す | 窓口の比喩（正面）＋白板の消された矢じり＋CVE番号は白板の素描に置く |

| 4 | 対応（個人・法人） | 更新後も、22:40に起動したプロセスが8.2.34のまま動いている（分割画面は無言） | ディスクとメモリの分割画面＋窓口の四拍目（再起動。言葉はここに一拍遅らせる）＋白板のゲートと修正版の一覧 |

- 通しの小道具：壁時計（22:58 → 03:12 → 07:10 → 07:31）、湯呑み、白板の手描き図、モニタ枠のテープ（`8.2.34` → `8.2.35`）。
- 読者：一般。専門語は出た場で言い換える。CVE 番号と版番号だけは正確に残す。
- 形式：学習漫画。橘が教え、ミナが読者の代わりに問う。1ページ＝1テーマ。
- 比喩の配役を固定する：客＝リクエスト、窓口係＝PHP のワーカー、机の上の半端な用紙＝前のリクエストの状態。P2 の客は「前の客の上着を着せられた次の客」であり、盗人ではない。比喩は P3 でも消さない（通りから見た窓口の列）。
