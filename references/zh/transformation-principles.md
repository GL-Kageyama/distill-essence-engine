# 转换原理

> 把任意输入转换成面向影像的好提示词的一般手法（＝菜谱的原理）。引擎的核心。distill-essence-engine 的参考文档。

种子（`~/Desktop/その他プロンプト/`）是把这些原理按我的喜好应用的**一个例子**。这里写的是覆盖整个范围（静止或动态，一切影像提示词）都有效力的**一般原理**，不依赖特定的形式或种子。

## 转换的流程

```
输入 → ①理解 → ②选定 → ③翻译 → ⑤构成 → ⑥样式 → ⑦负向 → 提示词
（④一致性・⑧忠实性不是工序，而是横跨全部工序的约束）
```

## 原理

### ① 输入理解 — 把握来的是什么

- 判定输入的种类（小说／文章／诗／对话记录／备忘 …）与本质。
- 特定要画的「什么」：主题・出现的要素・情感的推移・转折点・结局・反复出现的母题。

### ② 选定 — 避开平庸的一点

- **不画全部。** 只选值得记忆的瞬间・本质的场面・象征性的要素。
- 不选「把这篇文章画出来」所返回的平庸场面，而选超出预测、以必然令人信服的场面（＝「哇」）。
- 不字面说明。替换为视觉隐喻・象征・留白。
- **本质：会说话的一点。** 不画全部，以一点暗示整体（提喻）。选定避开平庸的「瞬间」（与翻译的平庸「象征」同根）。→ 详见 [选定](selection.md)。

### ③ 翻译 — 让抽象可视化

- 把内心・情感・主题转换成表情・身体・距离・光・影・道具・反复出现的母题・构图・留白。
- 语言说不出的，用画来展示。不说明，让观看者去发现。
- **本质：固有 × 间接。** 避开平庸的明喻（悲伤→雨），下降到这个故事固有的间接表现。深度由①理解的深度决定。→ 详见 [翻译](translation.md)。

### ④ 一致性 — 做成同一个世界

- 保持角色（脸・发型・年龄・体型・服装）与环境（地点・天气・季节・时间・建筑・照明）的连续性。
- 必须是同一部电影的连续镜头。不要做成不同插画的拼凑。

### ⑤ 构成 — 依形式而定的结构

- 采取与输出形式（分镜脚本／影像板／缩略图／封面／插画 …）相应的构成。
- 形式独立于内容，决定选定・翻译的结果如何排布。
  - 例：分镜脚本＝按故事节奏设计分格（大＝情感、小＝推移、特写＝发现、拉远＝孤立）
  - 例：缩略图＝一个一眼可懂的象征图形
  - 例：封面＝象征性的一场／角色集合
- **本质：间与关系。** 不是用要素，而是用排法（距离・留白・不对称）诉说。→ 详见 [配置](arrangement.md)。

### ⑥ 样式 — 可替换的层

- 把样式（水彩／手绘／POP …）的词汇配合内容来应用。
- 样式作为独立于内容的层来合成（可以只替换单轴）。

### ⑦ 负向 — 明示排除

- 明示排除要素（照片写实／数字抛光／文字／过度细节 …）。
- 与样式成对决定。

### ⑧ 忠实性 — 不变更原作

- 情感基调来自原输入（不强行 happy／悲剧／恐怖）。
- 不变更原作没有的事件・角色同一性・关系・结局。

## 原理的供给源

- **内容由来（从输入的分析导出）**：①理解 ②选定 ③翻译 ⑧忠实性
- **指定由来（从自然语言接收）**：⑤构成（形式） ⑥样式
- **横跨两者**：④一致性（源于内容、依形式而定） ⑦负向（与样式成对＋来自内容）

## 这些原理的用法

- 种子的 `[FIXED PROMPT]`（小说→影像板化）是这些一般原理**在一种形式中的具体化**。①〜⑧原样出现其中。
- 引擎读取输入，执行①，从指定（自然语言）接收⑤⑥的轴，应用②③④⑦⑧合成提示词。
- 有词典的话，用精炼过的词汇稳定⑤⑥的已知情形。
